# The shadcn-egui Claude Code plugin for 0.4

## Goal

The `egui-shadcn` plugin (0.3.2) copied a component module into a project.
Since 0.4.0 the components are crates on crates.io, so the plugin's
instructions no longer match the code. This spec rewrites the plugin for the
crates, renames it to `shadcn-egui`, and ties its version to the crate
version. The 0.4.0 release waits for this work, so the release notes cover
the plugin as well.

## Decisions

- The plugin holds two skills, named after their purpose:
  - `shadcn-egui:build-ui`: build or restyle an egui UI with the crate.
  - `shadcn-egui:port-component`: port a missing shadcn component, into the
    app or into this repository.
- The port skill serves both targets with one standard. In an app it uses
  only the crate's public API; upstream it uses the full repository tooling.
- The plugin version equals the crate version. Create release PR bumps it
  through `version_files`.
- Installation is through the repository's own marketplace. An entry in the
  oposs marketplace is out of scope.

## Skill `build-ui`

Description (the trigger): building or restyling a Rust egui GUI from a
shadcn or web design (screenshot, component code, preset code or
description) with the `shadcn-egui` crate; also an egui app that renders
without a GPU and is slow, pins a CPU core, redraws late or misroutes pointer
input.

The SKILL.md workflow:

1. Add the crate with `cargo add shadcn-egui` and only the `font-*` and
   `icons-*` features the design uses. The crate needs no `eframe`; it works
   with any egui integration.
2. Set the look once, right after the egui context exists:
   - a preset code from ui.shadcn.com:
     `Preset::from_code(..)?.apply(ctx, Mode::Dark)`, with the features the
     preset names (otherwise Inter and Lucide, and a log warning);
   - a `components.json`: a `Theme` from its style, base colour and radius;
   - nothing given: `Theme::vega_dark().apply(ctx)`.

   An app with fonts of its own uses `Theme::apply_with_fonts`. Apply again
   only when the mode or preset changes; read tokens with
   `Theme::current(ctx)`.
3. Decompose the design top-down: app shell, panels, the layout intent of
   each region, components and variants, token deviations.
4. Map with the references, `layout-map.md` first.
5. Build from `shadcn_egui::components` and `shadcn_egui::layout`. A missing
   component goes through `shadcn-egui:port-component`, not through ad hoc
   painting.
6. Verify visually: render a PNG and compare it with the design. The
   reference loop is an `egui_kittest` snapshot test as a dev-dependency;
   the skill carries a short test template. An app with its own screenshot
   path may use that instead.
7. Acceptance: the restraint of `reference::settings_ui` and the gallery
   example; the literal scan with its positive control (kept from 0.3);
   project deviations go into the theme construction
   (`let mut s = Style::nova(); s.button.… = …`), never into copies of crate
   code.

Kept from 0.3: the hard rules (single-pass layout, no `available_width()`
arithmetic, no invented state colours, `widget_info` on custom-painted
widgets) and the CPU-rendering reference. Removed: vendoring, the
`registry/` steps, the egui plus egui_extras dependency instructions.

The skill names its crate version as "the `shadcn-egui` version equal to
this plugin's version", so no second version string needs bumping.

`references/presets.md` covers `Preset::from_code`, `to_code`, `apply`,
`apply_with_fonts`, the font and icon features and the fallbacks (feature
off, translucent menu colour, `sera` falls back to `nova`, shadcn-svelte.com
codes are not supported).

`references/icons.md` covers `IconLibrary`, the `icons-*` features,
`IconView` and the icon slots of components. Custom SVG icons through
`tools/icongen` are described for a checkout of this repository only.

## Skill `port-component`

Description: a shadcn component or layout helper the UI needs is missing
from `shadcn-egui`; port it to the crate's standard, into the app or into
the shadcn-egui repository.

The shared part in SKILL.md:

1. Choose the target and say why. Upstream when working in a shadcn-egui
   checkout or when the component needs a `cn-*` marker `Style` does not
   have; in the app otherwise.
2. Source: the base `.svelte` file of shadcn-svelte at the commit in
   `tools/stylegen/PIN` (the skill gives the URL form) and the bits-ui
   primitive. Never port from memory or a screenshot.
3. Inventory: the `cn-*` markers and the styled states.
4. Mapping: markers to `Style` fields, states to `State` flags, `pick` in
   the order upstream joins the classes, `components::shared::interaction_state`
   for hover, active and focus.
5. Base classes quoted verbatim as `// base: "…"`; no style value in code
   without a quote or a `// token-ok:` comment.
6. egui sizing: the widget sizes itself before placement; size does not
   change on hover.
7. The behaviour list from the bits-ui primitive (with the Slider example)
   and the interaction-state rules, both kept from 0.3.
8. Snapshots in dark and light for each style in use; every PNG opened and
   compared with the shadcn-svelte docs page.
9. Dependency discipline: no new runtime dependency without a stated reason
   and the user's consent.

`references/in-app.md`: the public API (`Theme::current`, the `Style`
fields, `style::recipe::{pick, State}`, `components::shared::interaction_state`),
where the file goes (for example `src/ui/components/<name>.rs`), the literal
scan as the token check, `// base:` quotes kept for a later upstream port.
Limit: a marker missing from `Style` cannot be read in the app; the skill
stops and offers the upstream path. At the end it offers to open a PR to
`oetiker/shadcn-egui`, which needs the user's approval.

`references/upstream.md`: `tools/stylegen/markers.txt` and
`stylegen generate`, `crates/shadcn-egui/tests/tokens.rs` and its `PORTED`
list, `common::snapshot_all`, `stylegen drift` printing `drift: clean`, no
unsupported class in `tools/stylegen/reports/<style>.md`, a row in
`skills/build-ui/references/component-map.md`, a CHANGES entry, the gates
from `CLAUDE.md`.

## Checks

- Every `rust` code block in `skills/*/SKILL.md` and
  `skills/*/references/*.md` runs as a doctest, through
  `#[cfg(doctest)] #[doc = include_str!(…)]` items in
  `crates/shadcn-egui/src/lib.rs`. `cfg(doctest)` keeps the files out of
  `cargo package`. Snippets are small complete functions without hidden
  `# ` lines, which GitHub would show. A block that cannot compile on its own
  (a signature sketch) is marked `rust,ignore` and stays rare.
- `crates/shadcn-egui/tests/skills.rs`:
  - every module in `src/components/` except `shared` and `icon_raster` has
    a row in `component-map.md`;
  - every `font-*` and `icons-*` feature the skills name exists in
    `crates/shadcn-egui/Cargo.toml`;
  - `plugin.json`, the plugin entry in `marketplace.json` and the workspace
    version are equal.
- `.github/repo-infra.json` gets a `version_files` entry for the version in
  `plugin.json` and one for the plugin entry in `marketplace.json`.
- The `ri-ci-claude-plugin` CI job checks the manifests as before.
- Trial run before the merge: a fresh subagent installs the plugin from the
  branch, builds a small screen from a preset code with `build-ui` and ports
  RadioGroup into that app with `port-component`. The controller reviews the
  PNGs and fixes what the skills left unclear. Nothing from the trial run is
  committed.

## Repository changes outside the plugin

- `CLAUDE.md`: drop "`.claude-plugin/*.json` stay at 0.3.2"; add that the
  skills name crate APIs, so an API change updates the skills; the "Start
  here" links point at the new skill paths.
- `README.md`, section "The Claude Code plugin": what the two skills do and
  the install commands
  `/plugin marketplace add oetiker/shadcn-egui` and
  `/plugin install shadcn-egui@shadcn-egui`.
- `CHANGES.md` under [Unreleased]: the plugin is renamed to `shadcn-egui`,
  builds on the crate instead of copying code, and an `egui-shadcn` install
  must be removed and installed again. The 0.4 entry that says the plugin
  stays at 0.3.2 is replaced.
- `tools/icongen/tests/fixture_crate.rs`: the path of `icons.md` in its doc
  comment.
