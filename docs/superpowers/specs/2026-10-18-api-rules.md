# API rules for shadcn-egui components (draft)

Stage 2 draft of the plan `docs/superpowers/plans/2026-10-18-port-all-components.md`.
It moves into `plugin/skills/port-component/references/` with the stage 3
cleanup. The maintainer decided
`docs/superpowers/specs/2026-10-18-api-decisions.md` on 2026-10-19; each
rule states the decision of the entry it names ("Depends on D-n"), and
where the decision differs from that entry's recommendation, the rule
follows the decision. Examples are sketches of the target API, not
today's code. Where the maintainer answered a family bundle line or a
very-large sub-choice with "defer to the family PR", the rule that depends
on it stays a draft until that PR decides.

Every component, the 14 existing ones included, follows these rules. Where
egui has an idiom for the API shape, the rule uses it; behaviour and looks
follow upstream (P4). Idiom references name sections of the egui 0.34.3
idiom catalogue (§Widget builders, §Containers, …).

## Guiding principles

The maintainer accepted these principles on 2026-10-19; the decisions
apply them, and a later port weighs an open question against them.

- **P1 · Consistency.** One idea has one name, one type and one form
  across all components.
- **P2 · egui idiom.** The API reads like egui: builders, `show`,
  `Response`, egui's own types and names where they fit.
- **P3 · Mechanical rules.** A rule is one a later port can apply without
  asking; few concepts, few special cases.
- **P4 · Upstream decides behaviour and looks.** Behaviour and looks
  follow shadcn upstream at the pins; egui decides only the API shape.
  The crate does not copy egui behaviour where upstream behaves
  differently (maintainer: "we copy shadcn behavior!").
- **P5 · Misuse fails to compile.** Types make a wrong call a compile
  error rather than a silent no-op or a trap (borrow, off-by-one, a slot
  that changed its meaning).
- **P6 · Break once, cleanly.** A breaking change that buys a better API
  is acceptable; it lands in one release, with a deprecated forward where
  the old name can keep its meaning. Renames are fine before 1.0: there
  is no installed base yet (maintainer).
- **P7 · Few dependencies.** A new runtime dependency is optional,
  feature-gated and needs the maintainer's consent.
- **P8 · Scope.** Port what upstream styles and demos; leave out the rest
  with room in the shape to add it, and defer what only one family needs
  to that family's PR.
- **P9 · Exact colours.** Colours match upstream exactly; a look that
  cannot reach the exact colour is not acceptable, and the crate then
  paints the part itself or leaves the plain egui widget as egui draws it.

## Builder shape

- A component is a short-lived builder: `new(..)` takes the required data,
  chained `#[inline]` setters `fn x(mut self, ..) -> Self` set options,
  and it is consumed by `impl Widget` (leaf) or `show(..)` (container).
  Every builder carries `#[must_use]` with egui's message. Every variant
  and size enum of one component derives `Clone, Copy, Debug, Default,
  PartialEq, Eq` with upstream's default as `#[default]`; data-carrying
  enums derive what their fields allow; shared enums (`Orientation`,
  `Side`) have no `Default`, their default is per component. Variant and
  size enums are `#[non_exhaustive]`. Depends on D-14, D-131.
- A flag setter takes a `bool`: `.invalid(bool)`, `.expanded(bool)`. A
  setter without an argument exists only as a shortcut for one value of
  an enum setter: `.vertical()` is `.orientation(Orientation::Vertical)`.
  A flag that defaults to `true` keeps its positive name and is called
  with `false`. No positional `bool` parameters. Depends on D-3, D-16,
  D-17.
- Mode constructors: `new` for the common mode, a named constructor per
  other mode or alternative content (`Accordion::multiple`, `Kbd::icon`);
  `from_*` names an alternative input form (`Progress::from_value`,
  `Pagination::from_count`), as egui's `ComboBox::from_label`. Calendar
  and range-calendar are separate types (`Calendar`, `RangeCalendar`), as
  upstream ships them, so a range-only setter on a single calendar does
  not compile. Depends on D-25.
- Text: titles, labels, descriptions `impl Into<WidgetText>`; the body of
  a clickable widget `impl IntoAtoms`; text the component also reads as
  data `impl Into<String>`. Icons by value (`Icon` is `Copy`), colours as
  `impl Into<Color32>`. Depends on D-15, D-2, D-19.
- Disabled is the `Ui`'s for anything drawn into a `Ui`: leaf widgets
  have no `.enabled(bool)`; callers use `ui.add_enabled`. `.enabled(bool)`
  exists only where no `Ui` exists to disable or where upstream has a
  container prop. Containers whose upstream has a `disabled` prop
  that disables the container or its trigger (Field, FieldSet, AccordionItem,
  MenubarMenu, HoverCard) keep `.enabled(bool)`; data items without a `Ui`
  take `.enabled(bool)`; closure items use `add_enabled_ui`.
  Depends on D-1, D-79, D-80.
- Names: part functions carry the component prefix (`card_title`,
  `menu_separator`); a crate type may share an egui type's name, a helper
  type with another meaning may not; shortcuts take content only, never a
  variant. Depends on D-20, D-18.
- The theme may change the look of plain egui widgets (colours,
  spacing) only where it reaches upstream's exact colour, and never their
  behaviour (timing, focus, keys). It leaves plain `egui::ScrollArea` bars
  as egui draws them: a `ScrollStyle` thumb reaches only the nearest shared
  colour. Depends on D-135.

egui idiom: §Widget builders (builder struct + `impl Widget`, `#[inline]`
setters, `#[must_use]`), §Text, §Enabled state.

```rust
ui.add_enabled(ready, Button::new("Save").variant(ButtonVariant::Outline).icon(icons.check));
ui.add(Separator::new().vertical());
ui.add(Input::new(&mut email).hint_text("Email").invalid(email_bad));
```

Settled because: `Input::id_source` has been `#[deprecated]` since 0.5.0
and 0.6.0 shipped the alias for its one release, so the spec's alias rule
removes it in 0.7.0 (CP-06-8).

## Compound components

How a Svelte compound component (`<Card.Root><Card.Header>…`) maps to
egui:

1. **Parts that only render data become builder setters** on the root:
   title, description, media (`Card::new().title(..)
   .description(..)`). Prefixed free part functions (`card_title(ui, ..)`)
   stay for custom layouts. A header action is a part fn called first in
   the `show` closure (`card_action(ui, ..)`, D-48 (a')). Depends on D-46,
   D-48.
2. **The `show` closure holds the main content.** A secondary slot below
   it (footer) is a prefixed part fn called last inside the same closure
   (`card_footer(ui, ..)`, `dialog_footer(ui, ..)`), as upstream nests
   `Card.Footer` in `Card.Root`; the part tells its container through the
   `Ui` tag that it was drawn. One closure shares the caller's state with
   no borrow trap (stored builder closures and two closures in one call
   cannot), and it works on `egui::Modal`, which returns no handle. Side
   slots (item and attachment actions) are the closure itself, because the
   main content there is setter data; bubble reactions are setter data.
   Footers keep upstream's direction and the caller nests a layout
   inside. A container that holds a caller binding passes the current
   value (or a handle) to its closure, because the closure cannot read the
   borrowed variable itself (`Tabs::new(&mut tab, ..).show(ui, |ui, tab|
   ..)`). Depends on D-47, D-48.
3. **Items are data** when the widget needs them while it is closed or
   before it paints them (select and native-select: trigger text and
   typeahead; toggle-group; tabs list). Data items are item structs
   `XItem::new(value, content)` with setters (`.enabled`, `.icon`), and
   `impl From<(V, &str)>` lets the shortcut's tuples serve too. **Items
   are immediate-mode calls in the closure** when they can have arbitrary
   neighbours and carry the binding themselves (`radio_value`, menu
   items). A **handle** is passed to the closure when the parent holds the
   binding or places and separates items (accordion, breadcrumb,
   navigation-menu, message-scroller). Repeated uniform children come as a
   count plus an index closure (carousel slides, resizable panes); small
   fixed sets are data lists (avatar group, input-otp `.groups`). Table
   rows come from a handle method that returns a row builder with flag
   setters (`.selected(bool)`), over columns declared up front. Depends
   on D-26, D-55, D-17, D-122.
4. **A child learns its context from a `UiStackInfo` tag** the parent
   pushes (button in a button-group, kbd in a tooltip, item in a menu,
   bubble alignment from message); the child reads `ui.stack()`. A plain
   crate widget stacks the parent's recipe; no dedicated per-parent types.
   Depends on D-57, D-56.
5. **Root plus part types collapse into one widget** when the parts have
   no independent use (checkbox indicator, slider track and thumb, calendar
   grid). Depends on D-112.
6. **Upstream `Close` parts become `ui.close()`** (D-115, D-117).
   `Provider` parts map per component: the tooltip provider's delay
   becomes the crate tooltip's own default, upstream's 0 (D-40, D-130),
   the sidebar provider becomes the `Sidebar` root with state in memory
   (D-107).
7. **Groups without options are free functions** (`kbd_group`,
   `message_group`); groups with options are builders (`ItemGroup`).
   Depends on D-50.

egui idiom: §Containers (`show`, `InnerResponse`, `UiBuilder` stack info),
§Selection (`radio_value` runs), §Popups (`menu_button` items).

```rust
Card::new()
    .title("Create project")
    .description("Deploy your new project in one click.")
    .show(ui, |ui| {
        ui.add(Input::new(&mut name));
        card_footer(ui, |ui| { if ui.add(Button::new("Deploy")).clicked() { deploy(&name); } });
    });

RadioGroup::new().show(ui, |ui| {
    radio_value(ui, &mut plan, Plan::Free, "Free");
    radio_value(ui, &mut plan, Plan::Pro, "Pro");
});
```

## T1 · Selection

- A choice binds the caller's value: `&mut T` with `T: PartialEq`
  (+ `Clone` where the widget holds a list); `T = Option<X>` when the caller
  wants an empty state; multiple selection binds `&mut Vec<T>`. A widget
  that can clear its value by itself takes `&mut Option<T>` (toggle-group
  single, accordion single, calendar single `&mut Option<Date>`). Domain
  values stay domain types (`f32`, `Date`, a 1-based page). The
  questionnaire is the stated exception: its answers are data it
  validates, kept as indices in `&mut QuestionnaireState`. Depends on
  D-21, D-22, D-24, D-29, D-125.
- A value that matches no item marks nothing and shows the placeholder.
  Depends on D-22.
- Deselect by a second click is `.allow_deselect(bool)`, default as
  upstream, offered only where the bound type can be empty (on select in
  an `impl` block for `Select<Option<T>>`). Depends on D-23.
- Value-editing widgets write the value and call `mark_changed()`; the
  caller reads `changed()`.
- List shortcuts take the same value form as the builder:
  `tabs(ui, &mut v, &[(V::A, "A"), (V::B, "B")])`. Depends on D-27.
- Choice controls may carry their own label like egui's
  (`radio_value(ui, &mut v, x, text)`). The flag that marks a caller-chosen
  item is `selected(bool)`; the command item says `checked(bool)`; a menu
  checkbox item binds `&mut bool`. Depends on D-28, D-30, D-116.

egui idiom: §Selection (`selectable_value`, `radio_value`,
`ComboBox::show_ui`), §Response methods (`mark_changed`).

```rust
let items = [SelectItem::new(Fruit::Apple, "Apple"), SelectItem::new(Fruit::Pear, "Pear").enabled(in_season)];
let r = ui.add(Select::new("fruit", &mut fruit, &items));
if r.changed() { save(fruit); }
select(ui, "fruit2", &mut other, &[(Fruit::Apple, "Apple"), (Fruit::Pear, "Pear")]);
```

## T2 · Open state

- Anchored overlays keep their open flag in egui memory and accept an
  optional binding, named after the state: `.open(&mut bool)`. Tooltip and
  the "which item is open" state of menubar and navigation-menu stay in
  memory only. The flag is the crate's own per popup id, and every crate
  overlay closes through a crate overlay stack (egui's popup memory keeps
  one open popup, and egui closes a parent on a click in a nested popup's
  layer). Closing an overlay closes its descendants; a click outside the top
  overlay closes that overlay only, as bits' dismissible layer (D-128
  (o1)). Modals join the stack: the modal shell closes on a backdrop click
  only when it is the top entry, so it does not use egui's
  `ModalResponse::should_close()` as a whole. Depends on D-8, D-4, D-128,
  D-117.
- Modals take a required binding as a constructor argument,
  `Dialog::new(id, &mut open)`: a required binding goes into the
  constructor and an optional one into the D-4 setter, as in egui
  (`Checkbox::new(&mut b)` beside `Window::open`). Depends on D-31, D-4.
- Other state by kind: selection and disclosure belong to the caller
  (`&mut`), as upstream's `bind:value` and today's Tabs and Select (egui's
  `CollapsingHeader` keeps disclosure in memory; the crate departs from
  it); panel and view state (sidebar open, sidebar sub-menus, resizable
  layout, calendar month) live in memory with an optional binding;
  transient state (scroll mode, search text, toast queue) lives in memory
  only. Depends on D-32.
- Memory-owned state is read and driven through associated functions
  keyed by the component's id (`Sidebar::toggle(ctx, id)`); a caller-drawn
  trigger reads its `expanded` value from the binding, since the popup id
  derives from the trigger's `Response`;
  initial values only where upstream has a default prop; persistence is
  opt-in. Depends on D-33, D-34, D-35.

egui idiom: §Open state (the three forms), §Popups (`Popup::open_bool`,
`Popup::is_id_open`).

```rust
let resp = ui.add(Button::new("Open"));
Popover::new(&resp).open(&mut self.popover_open).show(|ui| { ui.label("Hi"); });
Dialog::new("confirm", &mut self.confirm_open).title("Delete file?").show(ctx, |ui| { /* … */ });
```

## T3 · Overlay

- Placement is `.align(RectAlign)` plus `.gap(f32)` on every anchored
  overlay, list pickers included; bits' `alignOffset` values are internal
  constants. Depends on D-7, D-36.
- The top overlay consumes Escape and closes alone: a crate hook
  registered through `Context::on_begin_pass` consumes the key at the
  start of the pass, before any crate overlay or `Modal` checks it, and
  closes the top entry of the previous pass's overlay stack; it consumes
  Escape only while that stack is not empty. Depends on D-38, D-128.
- Modals move focus in on open and return it to the trigger on close;
  anchored overlays return focus on close; Tab out of a non-modal overlay
  closes it. Depends on D-39.
- Hover overlays share `.open_delay`/`.close_delay` and open on keyboard
  focus; the tooltip leaves egui's tooltip machinery for an own popup to
  get them. Defaults are upstream's: tooltip 0 (the shadcn provider's
  `delayDuration`), hover-card bits' 0.7 s / 0.3 s; egui's global
  `tooltip_delay` is neither read nor changed. Hint overlays open for
  disabled triggers, action overlays do not. Depends on D-40, D-130,
  D-82.
- Pickers and menus share one list keyboard model: typeahead (1 s
  buffer), Home/End, PageUp/PageDown, loop, skipping disabled items. The
  pointer works as bits: a trigger opens on pointer down, and a
  press-drag-release chooses the item under the pointer. Depends on D-45,
  D-116.
- Dismissal setters only where upstream has a prop; dismissal itself
  behaves as upstream (navigation-menu hover items stay open on an outside
  touch). Panels on a window
  edge take the crate `Side`; start/end placements use `egui::Align`
  (`Align2` for corners), physical names in an LTR-only crate, set by a
  setter named for what it aligns. Components paint inside their
  allocation. Depends on D-41, D-42, D-43, D-44, D-132.
- An overlay builder on an existing trigger returns
  `Option<InnerResponse<R>>`; a call that draws its own trigger returns
  `InnerResponse<Option<R>>`; a modal returns `Option<InnerResponse<R>>`.
  Depends on D-9, D-31.
- Collision fallback is the opposite side, except the chart tooltip,
  which keeps egui's default. Depends on D-37.

egui idiom: §Anchoring (`RectAlign`, `align_alternatives`), §Popups
(`Popup`, `Modal`, `menu_button`), §Focus and keyboard.

```rust
Tooltip::new(&resp).align(RectAlign::RIGHT).show(|ui| { ui.add(Kbd::new("⌘K")); });
let r = dropdown_menu(ui, "Options", |ui| { ui.add(MenuItem::new("Copy")) });
```

Settled because: every egui floating container (`Area`, `Window`,
`Modal`) takes `&Context` in `show`, the modal shell is built on `Modal`,
and a `&mut Ui` would hide that the panel is not laid out in that `Ui`
(CP-11-3).

## T4 · Sub-parts

- See Compound components for the mapping. Passive part functions
  (separators, labels, headings) return `Response`. Depends on D-52.
- Media slots are `.icon(Icon)`, `.image(impl Into<ImageSource>)` and
  `.media(closure)`. Icon slots that may show a spinner take
  `impl Into<Glyph>`. Crate widgets and data items show icons through
  typed `.icon` slots, painted in the recipe's state colour; egui hosts get
  them through `IconAtom(icon)`, an image atom whose URI names an entry of
  a process-wide icon registry (D-129 (u1)), tinted with a caller colour or the text
  colour. Depends on D-49,
  D-59, D-58, D-129.
- Labelled groups are containers for data lists (select, native-select)
  and for command's filtered groups, which drop their heading when no item
  matches; menus use heading parts. Depends on D-51.
- Overlay builders take the trigger by `&Response`; helpers that decorate
  a trigger take it by value and return it. Depends on D-53.
- A component with free content offers both `ui.add(X::new(text))` and
  `X::new(..).show(ui, |ui| ..)` where upstream demos use both. Depends on
  D-54.

egui idiom: §Widget builders (two-step widgets), §Atom, §Response methods
(`on_hover_text(self)`).

```rust
let r = tooltip(ui.add(Button::new("?")), "Help");
ui.add(Alert::new("Heads up").description("You can add components."));
```

## T5 · Container

- In-flow containers return `InnerResponse<R>`; an own output type exists
  only where there is more to return, and its name ends in `Output`. The
  method is always `show`; a secondary slot is a part fn inside its
  closure (`card_footer(ui, ..)`), not a new verb. A crate type that
  mirrors an egui type keeps its `show_*` variants (`ScrollArea::show_rows`).
  Depends on D-13, D-60, D-61, D-47.
- In-flow containers take `&mut Ui`, floating ones `&Context` (Settled,
  see T3).
- Scroll areas are the crate's `ScrollArea`: it keeps egui's name and
  mirrors only the subset composites and demos use (constructors per axis,
  `max_height`, `max_width`, `auto_shrink`, `stick_to_bottom`, `id_salt`,
  `show`, `show_rows`), hides egui's bars and paints shadcn's (transparent
  track, the exact `bg-border` thumb, hover-only first, bits' other
  visibility types later). Composites use it: select and command lists,
  message-scroller, the sheet body in demos and docs, attachment group,
  table overflow. The theme does not style plain `egui::ScrollArea`.
  Depends on D-62, D-135.
- App-level services (sonner's toaster) are free functions on `&Context`
  that return a handle (`toast(ctx, ..) -> ToastId`); what happened comes
  back as events from the per-frame `Toaster::show(ctx)`. Depends on
  D-123, D-32.

egui idiom: §Containers (`InnerResponse`, `ScrollAreaOutput`,
`TextEditOutput`).

```rust
let r = Card::new().title("Stats").show(ui, |ui| ui.add(Progress::new(0.4)));
r.response.on_hover_text("40 %");
```

## T6 · Identity

- Components whose egui counterpart requires an id (modals and the
  toaster on `Modal`/`Area`, sidebar on `Panel`, select and native-select
  like `ComboBox`, chart on `egui_plot::Plot`) take `id_salt: impl Hash`
  in the constructor; every other stateful component uses its auto id and
  offers `.id_salt(impl Hash)`; overlays on a caller's trigger derive
  their popup id from it. Shortcuts take an id exactly when the
  builder requires one. Depends on D-12, D-64.
- Floating and app-level ids are global (`Id::new(salt)`), and panels are
  global like egui's `Panel::left(id)` although they are shown in a `Ui`;
  other in-flow ids are scoped (`ui.make_persistent_id`). Popups on a caller's trigger derive
  their id from it. Items use their index, or their value when they can
  reorder. Depends on D-64, D-65, D-66.

egui idiom: §IDs (`id_salt`, `make_persistent_id`, `Modal::new(id)`).

```rust
ui.add(Tabs::new(&mut tab, &[(Tab::General, "General"), (Tab::Users, "Users")]).id_salt("settings"));
```

## T7 · Orientation and direction

- One crate `Orientation { Horizontal, Vertical }`, set with
  `.orientation(..)` or the `.vertical()` shortcut. A crate type that
  mirrors an egui type keeps its per-axis constructors
  (`ScrollArea::vertical()`/`horizontal()`/`both()`). Depends on D-6,
  D-67.
- Group keyboard focus uses one shared roving-focus helper, configured
  per component as its primitive behaves (axes, Tab stop, wrap). Depends
  on D-68.
- Responsive breakpoints apply by default, as upstream: a media query
  (calendar `md:`, sonner, sidebar, pagination) reads the window width, a
  container query (field `@md/field-group`) the container's width, both
  through the breakpoint helper of D-133, the written-down exception to
  single-pass sizing. Where upstream makes the responsive mode an opt-in
  (field's `orientation="responsive"`), the crate does too
  (`.responsive(bool)`). Modes shadcn neither styles nor demos are left
  out. Depends on D-69, D-70, D-133.
- The crate is LTR only; placement types are egui's, whose names are
  physical. Depends on D-43, D-132.

egui idiom: §Direction and layout (Slider form: enum plus `.vertical()`),
§Focus and keyboard (`EventFilter`).

```rust
ui.add(Slider::new(&mut v, 0.0..=1.0).vertical());
```

## T8 · Sizing

- A content-sized widget takes `.width(f32)`: the requested width, capped
  to the available width (or the window), then raised to the content
  minimum. A widget that fills by default takes `.max_width(f32)` instead,
  never both (D-71 (s1); maintainer: renames are fine, so the rule rests
  on one width word per widget, not on keeping `Tabs::width`'s name).
  `.min_width(f32)` sets a floor; `f32::INFINITY` means fill. Text entry
  defaults to `Metrics::field_max_width`; select and native-select are
  content-sized (`w-fit`) as upstream and take `.width`. The cap over the
  available width is computed in one `layout` helper, which rule 6 of the
  porting standard points to; a breakpoint read goes through a second
  helper (container width or window width, D-69). Depends on D-71, D-72,
  D-133.
- Size variants are per-component enums whose middle value is `Default`.
  `size` is a pixel size only on widgets without variants
  (`Spinner::size(f32)`). Depends on D-73, D-74.
- Leaf widgets size themselves before placement (single pass) and never do
  `available_width()` arithmetic of their own (porting standard rule 6). A
  group that needs its children's count, size or ids (button-group,
  toggle-group, input-group, input-otp; radio-group's Tab stop, menu and
  command keys, command group hiding) collects them in one shared item
  registry (D-134 (w1)), stores them from the previous pass by id, gives each child its position flags (`FIRST`, `LAST`,
  `NOT_FIRST`, `NOT_LAST`) through a `Ui` tag, and calls
  `request_discard` when they change. Depends on D-134, D-75. A widget that
  needs a height takes the parent's, with a recipe or `Metrics` minimum,
  and offers `.height`. A recipe
  dimension gets a setter only when a shipped demo changes it. Depends on
  D-76, D-77, D-78, D-75.

egui idiom: §Widget builders (`add_sized`), §TextEdit (`desired_width`,
`f32::INFINITY`).

```rust
ui.add(Input::new(&mut q).max_width(240.0));
ui.add(Skeleton::new([f32::INFINITY, 16.0]));
```

- Labels wrap at the available width by default (a cleanup bug fix);
  whether Label also takes a wrap-mode setter is open. Depends on D-127.

## T9 · State flags

- A `State` flag exists for each state a recipe styles, and only then
  (porting standard rules 2 and 3); `State` becomes a `u128` behind a
  private field. One meaning per flag. Depends on D-11, D-92.
- `invalid` exists where a recipe styles `aria-invalid`; a group sets it
  for its parts, Field pushes it into its `Ui`. Validation is
  `.invalid(bool)` plus `.error(text)`. Depends on D-83, D-84.
- Display widgets become clickable with `.sense(Sense)`; `.link(bool)`
  gives the link look and role, with click and focus. Exclusive states with three or more values
  are enums. Depends on D-86, D-87.
- Animation where upstream animates (spinner, skeleton pulse, progress
  value, accordion and collapsible height, sheet slide, sidebar width,
  navigation-menu viewport, carousel slide, toast stack, shimmer,
  scroller), with upstream's timing, honouring `style.animation_time == 0`
  as reduced motion; caret blink is egui's. Depends on D-88.
- Every custom-painted widget reports `widget_info`; roles egui's
  `WidgetType` lacks go through `accesskit_node_builder`. Depends on D-89.
- Built-in Previous/Next buttons disable themselves at the ends; a caller
  override is `.next_enabled(bool)`/`.prev_enabled(bool)`, offered where a
  demo needs it (questionnaire). Depends on D-81.
- `read_only(bool)` is the name for "focus and navigate, no change"
  (calendar now, the name reserved for the others). Depends on D-85.

egui idiom: §Enabled state, §widget_info and accessibility.

```rust
RadioGroup::new().invalid(plan_missing).show(ui, |ui| {
    radio_value(ui, &mut plan, Some(Plan::Free), "Free");
});
ui.add(Badge::new("Docs").link(true));
```

## T10 · Shortcut functions

- A leaf whose common use is one call gets a shortcut, and so do value
  pickers (`select`, `native_select`, `tabs`, `toggle_group`,
  `pagination`, `calendar`, `range_calendar`); containers, popover-style
  overlays and data-heavy widgets (item, avatar, field, attachment, table,
  popover, hover-card, command) do not. Named exceptions,
  each mirroring an egui helper: `dropdown_menu`, `menubar_menu`,
  `context_menu` (egui `menu_button`, `Response::context_menu`) and
  `tooltip(resp, text)` (egui `on_hover_text`). Value shortcuts return
  `Response`; closure shortcuts return what their egui counterpart returns.
  Depends on D-90, D-10, D-9.
- Shortcuts take content only (no variant) and the same value form as the
  builder. Depends on D-18, D-27.

egui idiom: §Widget builders (`Ui` shortcut methods return `Response`).

```rust
if switch(ui, &mut dark).changed() { theme.toggle(); }
badge(ui, "New");
```

## T11 · Cross-cutting conventions

- Builder attributes, setter forms, text and icon types, names: see
  Builder shape. Depends on D-2, D-3, D-14, D-15, D-16, D-17, D-18, D-19,
  D-20.
- Icon slots are named per shape, plus a role-named slot wherever an
  icon library uses another icon for one role than for the shared shape
  (`calendar_prev`, `calendar_next`), so every library shows upstream's
  icon in every component; slots are added through icongen, and
  `IconSlots` is `#[non_exhaustive]`. Select's selector icon is the
  `select_trigger` slot, the plain down chevron has a new slot name, and
  `chevron_down` is gone, so old uses fail to compile. Depends on D-5,
  D-94.
- Binding setters are named after the state they bind (`.open(&mut
  bool)`); unlike egui's `Popup::open(bool)`, they bind rather than force
  one frame, which the module docs say. A setter binds optional state; a
  required binding is a constructor argument (D-31). Depends on D-4, D-31.

egui idiom: §Widget builders.

```rust
// Icon by value, flags with a bool, a binding named after its state.
ui.add(Button::new("Next").icon_end(icons.chevron_right).expanded(open));
Popover::new(&resp).open(&mut self.open).show(|ui| { ui.label("…"); });
```

## Generator and recipes

- Style values come from recipes; a recurring upstream class form gets a
  generator rule, not hand-written values (porting standard rule 5).
  Depends on D-95, D-98, D-99, D-77 (the bubble's `max-w-[80%]` becomes a
  recipe fraction field).
- `data-open` maps to `EXPANDED`; `data-[side=*]` on panels maps to four
  `SIDE_*` flags; group children get `FIRST`/`LAST`/`NOT_FIRST`/`NOT_LAST`;
  `SELECTED` keeps one meaning. Depends on D-91, D-93, D-92, D-134.
- A class that styles caller content egui renders itself is ignored with a
  reason that fits; an ignore never hides a class silently (the IGNORED
  entries for `*:` and `**:` get diagnostics in the cleanup). Depends on
  D-100.
- Colours match what the pinned docs page renders, exactly. Where svelte
  and the style CSS disagree, the pinned svelte source wins; the style CSS
  marker serves only where it gives the colours the svelte docs page
  renders (chart tooltip, checked in the chart PR). A literal colour of an
  upstream package (svelte-sonner's description) is ported as that
  literal. Upstream rules the browser never applies stay dead, as the
  browser renders them, and are flagged in the module docs; a blend the
  browser applies (the avatar's inner border) is reproduced as its
  resulting colour. Depends on D-95, D-96, D-97.
- Palette roles a component needs are added to `Palette` and the palette
  import. Depends on D-101.

egui idiom: none (crate generator).
