# API rules for shadcn-egui components (draft)

Stage 2 draft of the plan `docs/superpowers/plans/2026-10-18-port-all-components.md`.
It moves into `plugin/skills/port-component/references/` with the stage 3
cleanup, after the maintainer has decided
`docs/superpowers/specs/2026-10-18-api-decisions.md`. Until then each rule
is written as the recommendation of the entry it names ("Depends on
D-n"); a different decision changes the rule. Examples are sketches of
the target API, not today's code.

Every component, the 14 existing ones included, follows these rules. Where
egui has an idiom, the rule uses it; idiom references name sections of the
egui 0.34.3 idiom catalogue (§Widget builders, §Containers, …).

## Builder shape

- A component is a short-lived builder: `new(..)` takes the required data,
  chained `#[inline]` setters `fn x(mut self, ..) -> Self` set options,
  and it is consumed by `impl Widget` (leaf) or `show(..)` (container).
  Every builder carries `#[must_use]` with egui's message; every public
  enum derives `Clone, Copy, Debug, Default, PartialEq, Eq` with upstream's
  default as `#[default]`. Depends on D-14.
- A flag setter takes a `bool`: `.invalid(bool)`, `.expanded(bool)`. A
  setter without an argument exists only as a shortcut for one value of
  an enum setter: `.vertical()` is `.orientation(Orientation::Vertical)`.
  A flag that defaults to `true` keeps its positive name and is called
  with `false`. No positional `bool` parameters. Depends on D-3, D-16,
  D-17.
- Mode constructors: `new` for the common mode, a named constructor per
  other mode or alternative content (`Calendar::range`, `Kbd::icon`).
  Depends on D-25.
- Text: titles, labels, descriptions `impl Into<WidgetText>`; the body of
  a clickable widget `impl IntoAtoms`; text the component also reads as
  data `impl Into<String>`. Icons by value (`Icon` is `Copy`), colours as
  `impl Into<Color32>`. Depends on D-15, D-2, D-19.
- Disabled is the `Ui`'s: leaf widgets have no `.enabled(bool)`; callers
  use `ui.add_enabled`. Containers with an egui counterpart that has
  `.enabled` keep it; data items without a `Ui` take `.enabled(bool)`.
  Depends on D-1, D-79, D-80.
- Names: part functions carry the component prefix (`card_title`,
  `menu_separator`); a crate type may share an egui type's name, a helper
  type with another meaning may not; shortcuts take content only, never a
  variant. Depends on D-20, D-18.

egui idiom: §Widget builders (builder struct + `impl Widget`, `#[inline]`
setters, `#[must_use]`), §Text, §Enabled state.

```rust
ui.add_enabled(ready, Button::new("Save").variant(ButtonVariant::Outline).icon(icons.check));
ui.add(Separator::new().vertical());
ui.add(Input::new(&mut email).hint_text("Email").invalid(email_bad));
```

Settled because: `Input::id_source` has been `#[deprecated]` since 0.5.0
and 0.6.0 shipped the alias for its one release, so the spec's alias rule
removes it in 0.7.0 (CP-06-8).

## Compound components

How a Svelte compound component (`<Card.Root><Card.Header>…`) maps to
egui:

1. **Parts that only render data become builder setters** on the root:
   title, description, media, header action (`Card::new().title(..)
   .description(..)`). Prefixed free part functions (`card_title(ui, ..)`)
   stay for custom layouts. Depends on D-46.
2. **The `show` closure holds the main content.** Secondary slots
   (footer, actions, reactions) are builder closures; footers keep
   upstream's direction and the caller nests a layout inside. Depends on
   D-47, D-48.
3. **Items of a group are immediate-mode calls in the closure** when they
   can have arbitrary neighbours (`radio_value`, menu items, accordion
   items); **items are data** when the widget must know all of them
   before painting (select list, toggle-group, tabs list). A handle is
   passed to the closure when the parent places or separates items
   (breadcrumb, navigation-menu, message-scroller). Depends on D-26,
   D-55.
4. **A child learns its context from a `UiStackInfo` tag** the parent
   pushes (button in a button-group, kbd in a tooltip, item in a menu,
   bubble alignment from message); the child reads `ui.stack()`. A plain
   crate widget stacks the parent's recipe; no dedicated per-parent types.
   Depends on D-57, D-56.
5. **Root plus part types collapse into one widget** when the parts have
   no independent use (checkbox indicator, slider track and thumb, calendar
   grid, scroll-area bars).
6. **Upstream `Close` parts become `ui.close()`**; `Provider` parts become
   theme or style settings.
7. **Groups without options are free functions** (`kbd_group`,
   `message_group`); groups with options are builders (`ItemGroup`).
   Depends on D-50.

egui idiom: §Containers (`show`, `InnerResponse`, `UiBuilder` stack info),
§Selection (`radio_value` runs), §Popups (`menu_button` items).

```rust
Card::new()
    .title("Create project")
    .description("Deploy your new project in one click.")
    .footer(|ui| { ui.add(Button::new("Deploy")); })
    .show(ui, |ui| { ui.add(Input::new(&mut name)); });

RadioGroup::new(&mut plan).show(ui, |ui| {
    radio_value(ui, &mut plan, Plan::Free, "Free");
    radio_value(ui, &mut plan, Plan::Pro, "Pro");
});
```

## T1 · Selection

- A choice binds the caller's value: `&mut T` with `T: PartialEq`
  (+ `Clone` where the widget holds a list); `T = Option<X>` when the caller
  wants an empty state; multiple selection binds `&mut Vec<T>`. Domain
  values stay domain types (`f32`, `Date`, a 1-based page). Depends on D-21,
  D-22, D-24, D-29.
- A value that matches no item marks nothing and shows the placeholder.
  Depends on D-22.
- Deselect by a second click is `.allow_deselect(bool)`, default as
  upstream. Depends on D-23.
- Value-editing widgets write the value and call `mark_changed()`; the
  caller reads `changed()`.
- List shortcuts take the same value form as the builder:
  `tabs(ui, &mut v, &[(V::A, "A"), (V::B, "B")])`. Depends on D-27.
- Choice controls may carry their own label like egui's
  (`radio_value(ui, &mut v, x, text)`). The flag that marks a caller-chosen
  item is `selected(bool)`, `checked(bool)` where a checkmark is drawn.
  Depends on D-28, D-30.

egui idiom: §Selection (`selectable_value`, `radio_value`,
`ComboBox::show_ui`), §Response methods (`mark_changed`).

```rust
let r = ui.add(Select::new("fruit", &mut fruit, &[(Fruit::Apple, "Apple"), (Fruit::Pear, "Pear")]));
if r.changed() { save(fruit); }
```

## T2 · Open state

- Anchored overlays keep their open flag in egui memory and accept an
  optional binding, named after the state: `.open(&mut bool)`. Tooltip and
  the "which item is open" state of menubar and navigation-menu stay in
  memory only. Depends on D-8, D-4.
- Modals take the caller's `&mut bool` in `show`, as egui's `Modal` leaves
  the state to the caller. Depends on D-31.
- Other state by kind: selection and disclosure belong to the caller
  (`&mut`); panel and view state (sidebar open, resizable layout, calendar
  month) live in memory with an optional binding; transient state (scroll
  mode, search text, toast queue) lives in memory only. Depends on D-32.
- Memory-owned state is read and driven through associated functions
  keyed by `Id` (`Popover::is_open(ctx, id)`, `Sidebar::toggle(ctx, id)`);
  initial values only where upstream has a default prop; persistence is
  opt-in. Depends on D-33, D-34, D-35.

egui idiom: §Open state (the three forms), §Popups (`Popup::open_bool`,
`Popup::is_id_open`).

```rust
let resp = ui.add(Button::new("Open"));
Popover::new(&resp).open(&mut self.popover_open).show(|ui| { ui.label("Hi"); });
Dialog::new("confirm", "Delete file?").show(ctx, &mut self.confirm_open, |ui| { /* … */ });
```

## T3 · Overlay

- Placement is `.align(RectAlign)` plus `.gap(f32)` on every anchored
  overlay, list pickers included; bits' `alignOffset` values are internal
  constants. Collision fallback is the opposite side only. Depends on D-7,
  D-36, D-37.
- The top overlay consumes Escape and closes alone. Depends on D-38.
- Modals move focus in on open and return it to the trigger on close;
  anchored overlays return focus on close; Tab out of a non-modal overlay
  closes it. Depends on D-39.
- Hover overlays share `.open_delay`/`.close_delay` and open on keyboard
  focus. Hint overlays open for disabled triggers, action overlays do not.
  Depends on D-40, D-82.
- Dismissal setters only where upstream has a prop. Panels on a window
  edge take the crate `Side`; start/end placements use `egui::Align`
  (`Align2` for corners). Components paint inside their allocation.
  Depends on D-41, D-42, D-43, D-44.
- An overlay builder on an existing trigger returns
  `Option<InnerResponse<R>>`; a call that draws its own trigger returns
  `InnerResponse<Option<R>>`. Depends on D-9.

egui idiom: §Anchoring (`RectAlign`, `align_alternatives`), §Popups
(`Popup`, `Modal`, `menu_button`), §Focus and keyboard.

```rust
Tooltip::new(&resp).align(RectAlign::RIGHT).show(|ui| { ui.add(Kbd::new("⌘K")); });
let r = dropdown_menu(ui, "Options", |ui| { ui.add(MenuItem::new("Copy")) });
```

Settled because: every egui floating container (`Area`, `Window`,
`Modal`) takes `&Context` in `show`, the modal shell is built on `Modal`,
and a `&mut Ui` would hide that the panel is not laid out in that `Ui`
(CP-11-3).

## T4 · Sub-parts

- See Compound components for the mapping. Passive part functions
  (separators, labels, headings) return `Response`. Depends on D-52.
- Media slots are `.icon(Icon)`, `.image(impl Into<ImageSource>)` and
  `.media(closure)`. Icon slots that may show a spinner take
  `impl Into<Glyph>`. A crate `Icon` converts into an egui `Atom`. Depends
  on D-49, D-59, D-58.
- Labelled groups are containers for data lists and heading parts for
  closure lists. Depends on D-51.
- Overlay builders take the trigger by `&Response`; helpers that decorate
  a trigger take it by value and return it. Depends on D-53.
- A component with free content offers both `ui.add(X::new(text))` and
  `X::new(..).show(ui, |ui| ..)` where upstream demos use both. Depends on
  D-54.

egui idiom: §Widget builders (two-step widgets), §Atom, §Response methods
(`on_hover_text(self)`).

```rust
let r = tooltip(ui.add(Button::new("?")), "Help");
ui.add(Alert::new("Heads up").description("You can add components."));
```

## T5 · Container

- In-flow containers return `InnerResponse<R>`; an own output type exists
  only where there is more to return, and its name ends in `Output`. The
  method is always `show`. Depends on D-13, D-60, D-61.
- In-flow containers take `&mut Ui`, floating ones `&Context` (Settled,
  see T3).
- Scroll areas are egui's `ScrollArea`, styled by the theme. Depends on
  D-62.

egui idiom: §Containers (`InnerResponse`, `ScrollAreaOutput`,
`TextEditOutput`).

```rust
let r = Card::new().title("Stats").show(ui, |ui| ui.add(Progress::new(0.4)));
r.response.on_hover_text("40 %");
```

## T6 · Identity

- Floating components and those whose egui counterpart requires an id
  (modals, sidebar, select, native-select) take `id_salt: impl Hash` in
  the constructor; every other stateful component uses its auto id and
  offers `.id_salt(impl Hash)`. Shortcuts take an id exactly when the
  builder requires one. Depends on D-12, D-64.
- Floating and app-level ids are global (`Id::new(salt)`); in-flow ids are
  scoped (`ui.make_persistent_id`). Popups on a caller's trigger derive
  their id from it. Items use their index, or their value when they can
  reorder. Depends on D-64, D-65, D-66.

egui idiom: §IDs (`id_salt`, `make_persistent_id`, `Modal::new(id)`).

```rust
ui.add(Tabs::new(&mut tab).id_salt("settings").tab(Tab::General, "General"));
```

## T7 · Orientation and direction

- One crate `Orientation { Horizontal, Vertical }`, set with
  `.orientation(..)` or the `.vertical()` shortcut. Depends on D-6, D-67.
- Group keyboard focus uses one shared roving-focus helper, configured
  per component as its primitive behaves (axes, Tab stop, wrap). Depends
  on D-68.
- Responsive breakpoints count as desktop; a narrow branch a demo needs
  is an explicit opt-in. Modes shadcn neither styles nor demos are left
  out. Depends on D-69, D-70.
- The crate is LTR only; placement names stay logical (`Start`/`End`) so
  RTL can come later. Depends on D-43.

egui idiom: §Direction and layout (Slider form: enum plus `.vertical()`),
§Focus and keyboard (`EventFilter`).

```rust
ui.add(Slider::new(&mut v, 0.0..=1.0).vertical());
```

## T8 · Sizing

- `.width(f32)` sets an exact width, `.max_width(f32)` caps a filling
  widget, `.min_width(f32)` sets a floor; `f32::INFINITY` means fill.
  Text entry and selects default to `Metrics::field_max_width`. Depends on
  D-71, D-72.
- Size variants are per-component enums whose middle value is `Default`.
  `size` is a pixel size only on widgets without variants
  (`Spinner::size(f32)`). Depends on D-73, D-74.
- Widgets size themselves before placement (single pass) and never do
  `available_width()` arithmetic (porting standard rule 6); a widget that
  needs a height takes the parent's and offers `.height`. A recipe
  dimension gets a setter only when a shipped demo changes it. Depends on
  D-76, D-77, D-78, D-75.

egui idiom: §Widget builders (`add_sized`), §TextEdit (`desired_width`,
`f32::INFINITY`).

```rust
ui.add(Input::new(&mut q).max_width(240.0));
ui.add(Skeleton::new([f32::INFINITY, 16.0]));
```

Settled because: the maintainer put "label never wraps" among the
existing-crate bugs for the 0.7.0 cleanup, and wrapping at the available
width is what both `egui::Label` and upstream do (CP-07-3).

## T9 · State flags

- A `State` flag exists for each state a recipe styles, and only then
  (porting standard rules 2 and 3); `State` is widened to `u64` with a
  private field. One meaning per flag. Depends on D-11, D-92.
- `invalid` exists where a recipe styles `aria-invalid`; a group sets it
  for its parts, Field pushes it into its `Ui`. Validation is
  `.invalid(bool)` plus `.error(text)`. Depends on D-83, D-84.
- Display widgets become clickable with `.sense(Sense)`; `.link(bool)`
  gives the link look and role. Exclusive states with three or more values
  are enums. Depends on D-86, D-87.
- Animation only where it carries the information (spinner, skeleton
  pulse, shimmer, carousel slide, toast enter/exit), honouring
  `style.animation_time == 0`. Depends on D-88.
- Every custom-painted widget reports `widget_info`; roles egui's
  `WidgetType` lacks go through `accesskit_node_builder`. Depends on D-89.

egui idiom: §Enabled state, §widget_info and accessibility.

## T10 · Shortcut functions

- A leaf whose common use is one call gets a shortcut; containers,
  overlays and data-heavy widgets do not. Value shortcuts return
  `Response`; closure shortcuts return what their egui counterpart returns.
  Depends on D-90, D-10, D-9.
- Shortcuts take content only (no variant) and the same value form as the
  builder. Depends on D-18, D-27.

egui idiom: §Widget builders (`Ui` shortcut methods return `Response`).

```rust
if switch(ui, &mut dark).changed() { theme.toggle(); }
badge(ui, "New");
```

## T11 · Cross-cutting conventions

- Builder attributes, setter forms, text and icon types, names: see
  Builder shape. Depends on D-2, D-3, D-14, D-15, D-16, D-17, D-18, D-19,
  D-20.
- Icon slots are named per shape, added through icongen, and `IconSlots`
  is `#[non_exhaustive]`; `chevron_down` is the true chevron and Select's
  selector icon gets its own slot. Depends on D-5, D-94.
- Binding setters are named after the state they bind. Depends on D-4.

egui idiom: §Widget builders.

## Generator and recipes

- Style values come from recipes; a recurring upstream class form gets a
  generator rule, not hand-written values (porting standard rule 5).
  Depends on D-95, D-98, D-99.
- `data-open` maps to `EXPANDED`; `data-[side=*]` on panels maps to four
  `SIDE_*` flags; `SELECTED` keeps one meaning. Depends on D-91, D-93,
  D-92.
- A class that styles caller content egui renders itself is ignored with a
  reason that fits; an ignore never hides a class silently (the IGNORED
  entries for `*:` and `**:` get diagnostics in the cleanup). Depends on
  D-100.
- Where svelte and the style CSS disagree, the pinned svelte source wins,
  except where only the style CSS has the marker; upstream rules the
  browser never applies are ported for their evident intent and flagged.
  Depends on D-96, D-97.
- Palette roles a component needs are added to `Palette` and the palette
  import. Depends on D-101.

egui idiom: none (crate generator).
