# shadcn-egui 0.4.0 — published crate with shadcn presets: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn `egui_shadcn` into the crates.io workspace `shadcn-egui` 0.4.0,
where `Preset::from_code("b…")?.apply(ctx, Mode::Dark)` reproduces a shadcn
preset (style, base colour, theme, chart colour, font, heading font, icon
library, radius, menu colour, menu accent) on the 14 existing components.

**Architecture:** One Cargo workspace under `crates/`: a dependency-free leaf
crate `shadcn-egui-core` (icon and font data types), one crate per font and per
icon set (generated by tools), and `shadcn-egui` (theme, styles, palettes,
presets, components) that connects to the optional font and icon crates
through Cargo features. Upstream data (style CSS from shadcn-svelte;
`themes.ts`, `base-colors.ts`, `preset.ts`, `config.ts`, `font-definitions.ts`
from shadcn/ui, see §J) is turned into Rust by `tools/stylegen`; fonts are copied and described by `tools/fontgen`; icon sets
are converted to compact binary blobs (strokes plus pre-triangulated fills) by
`tools/icongen`. `Preset` is plain data that resolves to a `Theme`;
`Theme::apply` is the only code that installs fonts and writes egui style.

**Tech Stack:** Rust 2021, MSRV 1.92 (egui 0.34's), egui 0.34, egui_extras
0.34, `log` 0.4 (new runtime dependency), egui_kittest 0.34 + wgpu (dev only,
headless mesa snapshots), eframe 0.34 (example, dev only). Tools: usvg 0.48,
lyon_tessellation 1 (icongen only), skrifa (fontgen only), node ≥ 22.18 (runs
upstream TypeScript once to produce committed fixtures), curl, jq.

**Spec:** [`docs/superpowers/specs/2026-10-11-crate-and-presets-design.md`](../../specs/2026-10-11-crate-and-presets-design.md)
(commit `d3403af`, amended 2026-10-11 for D13: React lists only). Read it before Phase 0. Every phase file names the spec
sections it implements; the plan argues from the spec, so keep both open.

## Global Constraints

- Crate name `shadcn-egui` (lib `shadcn_egui`); GitHub repo `oetiker/shadcn-egui`; first crates.io release **0.4.0**; all crates share one version (lockstep) and track the latest egui (`egui = "0.34"`); MSRV follows egui (`rust-version = "1.92"`).
- `shadcn-egui-core` depends on nothing (spec: "nothing but egui"; it needs none). Font and icon crates depend only on `shadcn-egui-core`. Cargo forbids cycles, also through optional dependencies.
- Runtime `[dependencies]` of `shadcn-egui`: `egui`, `egui_extras` (default features off), `log`, `shadcn-egui-core`, `shadcn-egui-font-inter`, `shadcn-egui-icons-lucide`, and the optional font/icon crates. Nothing else. `lyon` and `skrifa` are tool-only.
- Features of `shadcn-egui`: `font-<upstream id>` per optional font, `icons-<lib>` per optional icon set, `fonts-all`, `icons-all`. Feature names use the upstream ids (`font-jetbrains-mono`, `icons-tabler`).
- Publish order: `shadcn-egui-core` → font and icon crates → `shadcn-egui`.
- crates.io refuses a `.crate` above 10 MB; the gate fails above **8 MB**.
- Licences (SPDX): code MIT (`LICENSE`); font crates `MIT AND OFL-1.1` or `MIT AND Apache-2.0`; icon crates `MIT AND ISC` (Lucide), `MIT AND MIT`→`MIT` (Tabler, Phosphor, Hugeicons if allowed), `MIT AND Apache-2.0` (Remixicon pin). A font that is not OFL-1.1/Apache-2.0 gets no crate and falls back to Inter.
- Remixicon ships pinned to its **last Apache-2.0 release** and is never updated (D14).
- `.claude-plugin/plugin.json` and `.claude-plugin/marketplace.json` keep version `0.3.2` and are not edited (D16).
- **Generated files are never edited by hand.** Fix the generator and regenerate: `crates/shadcn-egui/src/style/{generated,vega,nova,maia,lyra,mira,luma,rhea}.rs` and `palette/generated.rs`, `preset/generated.rs` (stylegen); `crates/shadcn-egui/src/fonts/registry.rs` and every `crates/shadcn-egui-font-*/src/lib.rs` (fontgen, from Phase 7); every `crates/shadcn-egui-icons-*/src/{lib.rs,icons.bin}` and `tests/icons/lucide.rs` (icongen).
- Tailwind `text-*` carries its line height: use `Theme::line_px(TextSize)`, never the font size, for row heights.
- Stack: `Style` is ~100 KB and `Theme::vega_dark()` needs ~200 KB of debug stack; a test builds styles and themes on a 256 KB thread. Never hold two `Style` values in one frame; new `Theme` fields must stay small (references, `Copy` data).
- Disabled fade only through `shared::disabled_painter`. Accessibility names come from `Response::labelled_by`; a widget never sets its own label.
- The repository is **public**: no private project names, hostnames or home paths in committed files. Paths in this plan use `$WT`, `$UP`, `$UP_REACT`, `$SCRATCH` (see Setup).
- Build parallelism ≤ 4 cores: every cargo command gets `--jobs 4`; every `cargo test` also `-- --test-threads 4`. Long commands run with a 600000 ms timeout and are never left running in the background at the end of a turn.
- Snapshots render headlessly (egui_kittest + wgpu, mesa software adapter). `UPDATE_SNAPSHOTS=1` regenerates. **Every snapshot change has a "user reviews the PNGs" stop step**; never continue past it without the user's approval.
- CHANGES.md: entries go under `## [Unreleased]` (no release header; CI manages it). Reader is a user; lead with what they see; ≤ 3 sentences; issue tag last in brackets if any.
- Commit messages end with a blank line and `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Nothing is pushed, merged into `main`, tagged or published without the user's explicit go-ahead. **`main` must not be pushed before the marketplace pin (Phase 8, Task 1)**: the marketplace tracks `main` HEAD and would ship a plugin without `registry/`.
- English for code, comments, docs.

## Review Focus

1. **Hostile or sloppy preset codes** (`" b0"`, `"b0\n"`, `"bé"`, `"😀"`, a 1000-character string, a lone `"b"`): a person pasting a code expects an `Err`, never a panic, overflow or a silently wrong preset. Pinned in Phase 4, Task 2 (`malformed_codes_are_errors_not_panics`).
2. **App-managed fonts across a light/dark toggle:** an app that called `apply_with_fonts(ctx, my_defs)` and then `apply(ctx)` for the dark variant of the same preset expects its own fonts to survive. Pinned in Phase 2, Task 3 (`app_fonts_survive_a_mode_toggle`).
3. **Encoding a preset that holds an unsupported value** (style `Sera`, a font whose feature is off): `to_code` must write the requested value, not the fallback, so the code still means the same on the website. Pinned in Phase 4, Task 5 (`to_code_keeps_values_that_fall_back`).
4. **Filled icons at a fractional scale** (`pixels_per_point = 1.25`) and at 50 % opacity: no darker seam where the fill and the fringe meet, no gap. Pinned in Phase 6, Task 4 (`filled_icon_has_no_seam_at_fractional_scale`).
5. **Switching presets with different fonts in a live context:** the frame between `set_fonts` and the atlas rebuild must not panic, and the next frame lays out with the new heading font. Pinned in Phase 2, Task 3 (`switching_fonts_on_a_live_context_does_not_panic`).

### Deviations from the suggested order, and why

- **`IconSlots`, `MenuColors`, `Theme::icons` and `Theme::menu` arrive in
  Phase 4, not Phases 5/6.** `Preset::theme()` (Phase 4) must fill every
  `Theme` field, and the fallback tests (§4.1 "icon library whose feature is
  off") need the icon field to exist. Phase 4 therefore adds the types, the
  fields and the builders, and switches the three components to read
  `t.icons.*` (a no-op visually: the slots hold the same Lucide paths).
  Phase 5 then teaches Select to draw with the menu colours, and Phase 6
  replaces the built-in paths by the generated icon crates.
- **`Palette::from_upstream` takes upstream id strings** (`"neutral"`,
  `"blue"`) so that Phase 3 does not need the preset enums, which Phase 4
  generates from `preset.ts` in upstream list order.
- **Phase 0 runs in the pre-workspace layout.** Its one code artefact (the
  variable-font proof test) moves with the crate in Phase 1 and is replaced
  by the permanent test in Phase 2.

### A. Crates, features, paths

- Crates: `shadcn-egui` (lib `shadcn_egui`), `shadcn-egui-core`, `shadcn-egui-font-<id>` (one per shipped upstream font id; `inter` is non-optional, all others optional, including `oxanium`), `shadcn-egui-icons-lucide` (non-optional), `shadcn-egui-icons-{tabler,phosphor,remixicon,hugeicons}` (optional; hugeicons only if `SETS.tsv` says `ship=yes`).
- Every crate has an entry in the root `[workspace.dependencies]`: `{ path = "crates/<name>", version = "0.4.0" }`. Crate `Cargo.toml` uses `version/edition/rust-version/repository.workspace = true`.
- Features of `shadcn-egui`: `font-<id> = ["dep:shadcn-egui-font-<id>"]`, `icons-<lib> = ["dep:shadcn-egui-icons-<lib>"]`, `fonts-all`, `icons-all`. There is no `font-inter` and no `icons-lucide` feature. From Phase 7 on, fontgen rewrites the font features and dependencies between the markers `# BEGIN fontgen` and `# END fontgen` in `crates/shadcn-egui/Cargo.toml`.
- `shadcn-egui` dev-depends on `shadcn-egui-font-oxanium` directly, so heading-font tests run with default features.
- `log = "0.4"` becomes a runtime dependency in Phase 4. Integration tests use it through the normal dependency.
- Generated files, never hand-edited:
  - `crates/shadcn-egui/src/palette/generated.rs` (stylegen, Phase 3)
  - `crates/shadcn-egui/src/preset/generated.rs` (stylegen, Phase 4)
  - `crates/shadcn-egui/src/fonts/registry.rs` (fontgen, Phase 7; hand-written `src/fonts.rs` until then)
  - `crates/shadcn-egui-font-*/src/lib.rs` (fontgen, Phase 7)
  - `crates/shadcn-egui-icons-*/src/{lib.rs,icons.bin}` (icongen, Phase 6)
  - `crates/shadcn-egui/tests/icons/lucide.rs` (icongen `--out` mode)
- Fixture copies of the upstream sources live in `tools/stylegen/tests/fixtures/`: from `$UP_REACT` `themes.ts`, `base-colors.ts`, `preset.ts`, `config.ts`, `font-definitions.ts` (plus `SHADCN-UI-LICENSE`); from `$UP` the existing `style-*.css` (plus `SHADCN-SVELTE-LICENSE`). `stylegen generate` refreshes these copies from the two checkouts before generating. `libraries.ts` is no longer read (§J).

### D. Icons (Phase 6)

```rust
// shadcn_egui_core — Icon changes:
pub struct Icon { pub name: &'static str, pub size: f32, pub shape: IconShape }   // size is always 24.0 for generated sets
#[derive(Clone, Copy, Debug, PartialEq)] pub enum IconShape { Segs(&'static [Seg]), Blob(BlobRange) }
#[derive(Clone, Copy)] pub struct BlobRange { pub blob: &'static [u8], pub start: u32, pub len: u32 }
//   PartialEq: ptr::eq(blob.as_ptr()) && start && len; Debug: "BlobRange { start, len }" (never dump bytes)
impl Icon {
  pub fn segs(&self) -> SegIter;               // pub enum SegIter { Slice(slice::Iter<'static, Seg>), Words(..) } : Iterator<Item = Seg>
  pub fn fill_mesh(&self) -> Option<FillMesh>; // None for Segs or an empty fill section
}
pub struct FillMesh { pub vertices: Vec<[f32; 2]>, pub indices: Vec<u16>, pub contours: Vec<Vec<([f32; 2], [f32; 2])>> } // (point, outward miter)
```

Blob record per icon. All values are little-endian 16-bit; icon coordinates are normalised to the 24-unit box (`x * 24 / viewBox`).

- **Stroke section:**
  - `stroke_len: u16` (number of 16-bit words that follow).
  - Then opcodes, each followed by its i16 coordinates: `0=M(2)`, `1=L(2)`, `2=Q(4)`, `3=C(6)`, `4=Z(0)`.
  - Coordinates are quantised at `round(v * 1024)` as i16, so the range is −32..32 units; icongen errors outside it.
- **Fill section** (always present; all zero means no fill):
  - `nv: u16, ni: u16, nc: u16`
  - `nv × (x: i16, y: i16)` mesh vertices
  - `ni × u16` triangle indices
  - `nc ×` contours, each `{ len: u16, len × (x i16, y i16, mx i16, my i16) }`
  - The miter is quantised at `round(m * 8192)`; |m| ≤ 2.
- `Icon` consts are a name plus a range into one `const BLOB: &[u8] = include_bytes!("icons.bin")` per crate.

icongen work (tool-only dependencies `usvg 0.48`, `lyon_tessellation = "1"`):

- Filled paths are no longer an error.
- Curves are flattened with tolerance `0.02` units (consecutive duplicate points are dropped, and so is the closing point when it equals the first).
- lyon `FillTessellator` with the SVG fill rule (NonZero/EvenOdd) produces the mesh.
- Outward normals per contour vertex:
  - For each edge, the left normal is flipped if a probe point `mid + left * 1e-3` lies inside the fill (winding number under the fill rule).
  - The vertex miter is `normalize(n1 + n2) / max(dot(m, n1), 0.5)`, so it is clamped to length 2.

icongen CLI:

- `--out FILE --module-path PATH --provenance TEXT SVG…` stays. It emits `IconShape::Segs` and errors on fills; it is used for `tests/icons/lucide.rs`.

  - the crate doc from the provenance;

- It also writes `DIR/src/icons.bin`.
- New: `--measure` prints the icon count, blob bytes and the largest icons.
- Slot icons per library:

  | Library | check | chevron_down (Select trigger) | close |

### G. Spec inconsistencies found and decisions (apply them)

1. *(Superseded 2026-10-11, §J.)* The icon-library order comes from React `preset.ts` `PRESET_ICON_LIBRARIES` (lucide, hugeicons, tabler, phosphor, remixicon), which differs from both `libraries.ts` key orders. `libraries.ts` is not read.

3. `THEMES = [...BASE_THEMES, 17 overlays]`. Choosing a base name as `theme` overlays the whole base palette. The merge looks theme ids up in BASES first, then OVERLAYS.
4. `destructive-foreground` is absent upstream. Generated palettes use `oklch(0.985 0 0)` in both modes, the current value.
5. The Select trigger icon differs per library (Tabler `IconSelector`, Hugeicons `UnfoldMoreIcon`, Phosphor `CaretDownIcon`, Remix `RiArrowDownSLine`). The slot keeps the spec name `chevron_down` and maps to the upstream icon of each library (table in D).
6. Hugeicons and Tabler can mix strokes and fills, so every blob record has both a stroke and a fill section.

Further decisions:

- Core has no dependencies.
- `RadiusChoice::Px` is a generated extra variant.
- The setter for the `theme` field is `.theme_color(..)`, because `Preset::theme(mode)` is the resolver.
- `MenuColors` uses `Option` fields: `None` means the theme's own palette and dark flag. This satisfies "`MenuColors::default()` uses the theme's own palette".
- Fixture text formats are parsed without serde.
- CHANGES entries go under `[Unreleased]` without a header.

### I. Known pre-existing issues to offer the user

Found while writing the plan; not fixed by it. Offer each to the user
after the phase that touches it; do not fix them off-plan.

- `IconView` sets its own accessible name from `icon.name`, against the
  rule that a widget never sets its own label (accesskit prefers it over
  `labelled_by`, so a caller's label is ignored). Phase 6 keeps the
  behaviour (icongen still writes `name`).
- The repository is not rustfmt-clean (`cargo fmt --check` reports about
  950 diffs at 20ba879), while the repo-infra CI (Phase 8 Task 5) runs
  `cargo fmt --check`.
- Overlapping filled paths in one icon (fixture `overlap.svg`) are drawn as
  overlapping triangles, so under alpha (a disabled widget, a translucent
  menu) the overlap blends twice and looks darker. Unresolved in Phase 6.
